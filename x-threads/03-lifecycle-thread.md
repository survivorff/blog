## 推文序列（1/10）

### 1/10 — Hook

```
你在交易平台点击「买入」的那一刻，对你来说是一个动作。

对平台来说，是 10+ 个环节的流水线启动。每一步都可能失败。

作为做 Solana 交易基建 2 年的人，带你走完这条流水线：🧵
```

### 2/10 — 流水线全景

```
一笔交易的完整路径：

1. 参数校验
2. 路由选择
3. 交易构建
4. 交易模拟
5. 签名
6. 提交（Jito Bundle 或直接 RPC）
7. 传播到 Leader
8. 排队进入区块
9. 执行
10. 确认
11. 状态同步

新手做 Bot 常常只看到"发一笔交易"这一步，不知道前后还有十几步。
```

### 3/10 — 路由是一门学问

```
同一个 Token 可能在多个 DEX 上有流动性：
- PumpSwap 60%
- Raydium 30%
- Meteora 10%

买入 1 SOL 的最优策略可能不是走最深的池子，而是拆单：
0.6 → PumpSwap
0.3 → Raydium
0.1 → Meteora

每个池子价格影响更小，总滑点最低。
```

### 4/10 — 交易模拟：被忽视的关键步骤

```
模拟是提交前的"空跑"。好处：

1. 提前发现会失败的交易
2. 获取准确的 CU 消耗
3. 检测蜜罐（买入显示返回 0 Token）

跳过模拟能省 50-100ms，但失败率会爆炸。

只有极端狙击场景才建议跳过。
```

### 5/10 — 托管 vs 非托管的速度差

```
签名环节的时间差：

托管钱包：0ms（后端直接签）
非托管钱包：2-10 秒（等用户点"确认"）

这就是为什么专业 Meme 交易平台几乎都提供托管选项。

安全性？用户自己也愿意接受这个权衡 —— 速度在这个场景优先级更高。
```

### 6/10 — Jito 还是直接提交

```
两种提交方式：

A. 直接 RPC：简单、快，但无 MEV 保护
B. Jito Bundle：防夹、可原子执行，稍慢

实战策略：
- 普通小额：A
- 大额/狙击：B

高级玩法：两种同时提交，哪个先成功用哪个。多付一份费用，换最大落链率。
```

### 7/10 — 成功 vs 失败 vs Dropped

```
交易有三种结局：

✅ Success：正常成交
❌ Failure：被打包但执行失败（滑点、CU 不足）
🗑️ Dropped：没进区块（Gas 不够优先）

用户看到都是"失败"，但处理完全不同：
- Failure → 调参数重试
- Dropped → 加 Priority Fee

平台要区分这两种才能给出正确反馈。
```

### 8/10 — 失败处理比成功路径更重要

```
专业平台 70% 的代码在处理失败：

- Blockhash 过期 → 用新的
- CU 不足 → 增加重试
- Priority Fee 不够 → 提高重试
- Jito Bundle 失败 → 降级为直接提交
- RPC 错误 → 切备用

好平台让用户感觉"很少失败"。差的把错误直接抛给用户。
```

### 9/10 — 延迟预算

```
一笔典型 Meme 交易的时间预算：

校验+路由+构建：50ms
模拟：50-100ms
签名（托管）：0ms
提交 Jito：50-100ms
传播：100-200ms
等区块：400ms
执行+确认：1-2s
状态同步：100ms

总计：2-3 秒

快于这个数字是特殊优化，慢的话说明某环节出了问题。
```
