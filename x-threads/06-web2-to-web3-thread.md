# X Thread：从 Web2 转 Web3 后端的 4 年心路

> 推广文章：https://blog.frankfu.cloud/posts/web2-to-web3-survival/
> 发布策略：开博第 20 天左右，"人设展示"的 Thread
> 目标：破圈，不只是开发者，所有工程师都能看

---

## 推文序列（1/10）

### 1/10 — Hook

```
4 年前我从传统后端（7 年经验）转到 Web3。

朋友都觉得我疯了。稳定工资不要，去"明天可能就没了"的行业。

4 年过去，做了一些事也踩了一些坑。把真实经历写出来，给还在考虑的人参考。🧵
```

### 2/10 — 转的动机

```
我当时转的理由很具体：

1. 传统后端的天花板开始清晰。做到 P7，往上是管理能力的竞争，我不喜欢。

2. Web3 对我的技术栈是加法。分布式、高并发、实时系统 —— 恰好是链上基建最需要的。

3. 新行业的早期机会。Web2 后端已是红海，Web3 还是蓝海。

**没有"财富自由"的预期**。见过太多人冲着暴富进来，亏得很惨。
```

### 3/10 — 最初 3 个月的挫败感

```
我严重低估了学习曲线。

Day 1: 读 Bitcoin 白皮书。看懂了大概。
Week 2: 以太坊黄皮书，字节码让我头疼。
Month 2: 看 Uniswap V2 源码，发现以为懂的都是表面。
Month 3: 在测试网写了个 reentrancy 漏洞合约。

最让我受挫的不是技术，是 **mental model 的转变**。
```

### 4/10 — 心智模型的切换

```
传统后端：我的代码在我的服务器上运行
智能合约：代码一旦部署就不可变，全世界都能看，漏洞会被立刻利用

传统后端：数据库出错可以回滚
链上操作：一旦确认就是永久的

这种"世界观的切换"花了我 3 个月才真正适应。
```

### 5/10 — 意外收获 1：重新理解分布式

```
Web3 让我重新学了一遍分布式系统。

我以前懂的是"受控环境下的分布式"：自己的数据中心、服务器、网络。

Web3 是"敌对环境下的分布式"：
- 节点可能作恶
- 网络可能被审查
- 用户可能就是攻击者
- 信任不能假设，只能验证

这种思维反过来让我把 Web2 系统设计得更 robust。
```

### 6/10 — 意外收获 2：对"钱"的敏感度

```
传统后端你写的是业务逻辑。
Web3 你写的是钱。

这个差异看起来小，落到代码上是巨大的：
- 每一行代码都可能导致真金白银流失
- 安全优先级永远高于功能
- 审计、测试、形式化验证成为必备
- 边界情况的敏感度要提升一个数量级

这种训练让我对"严谨"有了新的理解。
```

### 7/10 — 踩过的坑

```
3 个核心教训：

❌ 低估链上的复杂度（Gas 优化、MEV、并发模型完全不同）
❌ 过早尝试 Web3 原生设计（用户根本不在乎去中心化）
❌ 太快跳进热点（每 3 个月一个新叙事）

现在我只专注：**交易系统 + 高性能基础设施**。这是我技术栈的延伸，建立真正的护城河。
```

### 8/10 — 收入对比（大家关心的）

```
传统后端（2022）：
- 北上广深大厂 P7: ¥80-120 万
- 二线好公司: ¥50-80 万

Web3（2025）：
- 中型加密公司: $60-150K 年包（含 Token）
- 头部项目核心: $300-500K+
- 自由职业: $150-400/小时

但注意：
- Token 可能归零
- 熊市招聘收缩
- 没有传统意义的稳定

**上限高很多，下限也低很多。**
```

### 9/10 — 给正在考虑的人

```
有 3-5 年经验的 Web2 后端：

1. 不要全职一步到位，先用业余时间学
2. 积累开源作品，公开 GitHub 比简历重要
3. 加入好的 TG/Discord 社区
4. 准备好适应不稳定
5. 专注一个方向做深，不要贪多

刚毕业的：
Web3 不是你的第一站。先去好的传统后端打基础，3 年后再考虑。
```

### 10/10 — 4 年后的自己

```
回头看 4 年前的决定：

物质：多赚了一些，没有预期多
技术：栈扩展了，但经历了"重学习"痛苦
认知：接触到聪明的年轻人，重新理解"去中心化"、"信任"

如果重来：还是会转。但会更晚转（技术更扎实），更专注（不贪多）。
```
